      A vault is just a folder
      
        
      ~/Plainfile/
├─ inbox/               quick capture lands here
├─ projects/
│  └─ website-relaunch/
│     ├─ index.md
│     ├─ kickoff-call.md
│     └─ tasks/  write-pricing-copy.md …
├─ journal/             2026-11-21.md
├─ people/              dana.md
├─ reference/
├─ .plainfile/
│  ├─ config.md        views, tag colors, templates
│  ├─ views/           saved queries, also markdown
│  └─ index.db         cache only, safe to delete
└─ README.md
      
        
      Copy the folder to a USB stick, sync it with any service, or open it in another editor. Nothing is stored anywhere else. If the app disappears, you still have readable files.
      
      
      
      
      
        
      Two kinds of task, one list
      
        
      Inline: a checkbox line inside any note. Good for meeting notes and journals.
      
        
      - [ ] Send logo files @dana due:2026-11-23 #launch
      
        
      File task: one file per task, for work with its own notes, status and history.
      
        
      ---
title: Write pricing page copy
status: doing
due: 2026-11-24
repeat: none
---
      
        
      The hub scans both and shows them together. Each row links back to the exact file and line.
      
      
      
      
      
        
      Views are saved queries
      
        
      ---
view: Today
where: done = false AND due <= today
sort: due, project
---
      
        
      Board, list, calendar and table are different layouts of the same query. Views live in .plainfile/views/ so they travel with the vault.
      
      
      
      
      
        
      How edits stay safe
      
        
      The app edits the smallest piece of text it can: one checkbox, one frontmatter line. It never rewrites a whole file or reformats your prose.
      
        
      It watches the folder. If you edit a file in another editor, the hub updates. If a sync tool creates a conflict copy, the hub shows both and lets you pick.
      
        
      The index database is rebuilt from the files at any time, so it is never the thing you back up.
